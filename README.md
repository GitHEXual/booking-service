# Сервис записи на встречи с приватной видеоконференцией

Аналог Calendly: эксперт задаёт виды встреч и часы приёма, гость открывает
публичную ссылку, видит свободные слоты и отправляет заявку. Заявка занимает
место в слоте. Собрав состав, эксперт одним действием закрывает слот, и в Телемосте
создаётся приватная встреча, а участники получают письма со ссылкой и паролем.

## Как устроен продукт

**Гость не бронирует время, а подаёт заявку.** Слот это время со множеством гостей,
и кто именно придёт, решает эксперт. Он видит список, исключает лишних и
закрепляет состав одним действием. Значение предела гостей, равное 1, даёт обычную
одиночную запись, отдельного вида встречи для этого не требуется.

**Закрепление состава это точка невозврата.** Слот закрывается, состав больше не
меняется, создаётся встреча, раздаётся доступ. Убрать гостя после этого
невозможно: письмо отозвать нельзя, а пароль один на весь состав.

**Встреча приватная за счёт доступа, а не ссылки.** Ссылка может оказаться в
истории браузера или в переписке, поэтому её недостаточно: участники получают
пароль письмом, а в встрече включена комната ожидания, где впускает эксперт.

## Решения, которые приняты

- Стек: FastAPI, React 19 и Vite, PostgreSQL, SQLAlchemy 2.0 async, Alembic.
- Эксперт входит через OAuth Яндекс ID. Гость не регистрируется.
- Слот связан с множеством гостей. Предел `max_guests` настраивается на вид
  встречи, значение 1 даёт одиночную запись.
- Эксперт исключает гостей и закрепляет состав. После закрепления состав
  неизменен.
- Встреча создаётся в Телемосте при закреплении состава, пароль генерирует
  приложение, комната ожидания включена.
- Окно сбора состава и дедлайн закрепления настраиваются для каждого вида встречи.
- Расписание это недельное правило, без исключений по датам.
- Письма: эксперту про заявку, участникам про закрепление со ссылкой и паролем,
  гостю про исключение, гостю про протухание, всем про отмену встречи.
- Персональные данные шифруются на уровне колонок, поиск идёт по слепому
  индексу.

## Что ещё не решено

| Вопрос | Почему это важно |
|---|---|
| Токен Телемоста | Нужен `ClientID` приложения «Для доступа к API» и сам токен. См. `.env.example`, раздел про Телемост. Пока их нет, встреча не создаётся, но закрепление состава работает |
| ClientID и пароль приложения входа | Нужны для OAuth Яндекс ID. См. `.env.example`, раздел про Яндекс ID |
| Почтовый домен и ящик | Нужен ящик Яндекса, пароль приложения и записи SPF, DKIM, DMARC, иначе письма уходят в спам |
| Где размещается сервис | Требование говорит об облачном хостинге, конкретная площадка не выбрана |
| Синхронизация с внешними календарями | Без неё занятость знает только сервис. Осознанное ограничение, зафиксированное в PDR |

## Настройка

```bash
cp .env.example .env
```

В `.env` ключи для локальной разработки уже сгенерированы. Остаётся заполнить
доступы Яндекса, токен Телемоста и данные почтового ящика. Формат каждой
переменной и место, где её взять, описаны в `.env.example`.

## Порядок работы

1. Каркас проекта: `pyproject.toml`, Docker Compose с PostgreSQL, настройки,
   переменные окружения с ключами шифрования.
2. Схема базы и миграции Alembic, включая частичные индексы из ADR 0004.
3. Движок слотов как чистые функции плюс тесты.
4. Эндпоинты гостя: виды встреч, слоты, заявка, мои заявки, отзыв.
5. OAuth Яндекс ID.
6. Панель эксперта: расписание, виды встреч, списки гостей по слотам,
   исключение, закрепление состава.
7. Письма с outbox, пять поводов.
8. Телемост: генерация пароля, комната ожидания, повторные попытки.
9. Контракт и тест на дрейф, сквозные тесты Playwright.
