# ADR 0007. Вход эксперта через OAuth Яндекс ID

- **Статус:** принято
- **Дата:** 7 октября 2026

## Контекст

Требование задачи: вход по SSO. Своего пароля у сервиса быть не должно. Кроме
входа, токен эксперта нужен, чтобы создавать встречи в Телемосте от его имени
(ADR 0009).

## Решение

Одно OAuth-приложение Яндекса закрывает и вход, и Телемост. Поток со кодом и
PKCE: сервис отправляет человека на Яндекс, проверяет `state`, меняет код на
токен, читает профиль и находит или создаёт пользователя по `yandex_id`.

Токен хранится в таблице `oauth_tokens` зашифрованным (ADR 0005), потому что он
даёт доступ к аккаунту. Он же используется для вызовов Телемоста.

Сессия сервиса своя: в куке `HttpOnly` лежит случайный токен, в базе только его
HMAC под `SESSION_SECRET`. Выход удаляет строку сессии, а не ждёт истечения срока.

Первый вошедший получает роль `organizer`. Роли `admin` и `organizer` задаются
полем в таблице, из интерфейса не меняются.

## Последствия

- **Плюс:** паролей в сервисе нет, целый класс задач отпадает.
- **Плюс:** вход, профиль и доступ к Телемосту идут одним приложением.
- **Минус:** нужен доступ к Яндексу; без него не войти.
- **Минус:** пока приложение не прошло модерацию, на экране входа видно
  предупреждение, и часть людей на нём отваливается.
