# ADR 0009. Встреча в Телемосте

- **Статус:** принято
- **Дата:** 7 октября 2026

## Контекст

Требование задачи: интеграция с сервисом видеозвонков. Нужно создать реальную
встречу и выдать на неё ссылку. Внешний сервис не участвует в нашей транзакции и
может быть недоступен.

## Решение

Встречу создаёт фоновый воркер сразу после первой заявки на слот, а не перед
началом. Токен берётся у эксперта из `oauth_tokens` (ADR 0007): встреча
создаётся от его имени, и он в ней организатор. Один слот это одна встреча.

Запрос: `POST https://cloud-api.yandex.net/v1/telemost-api/conferences` с
заголовком `Authorization: OAuth <токен>` и телом `waiting_room_level: PUBLIC`.
Ответ `201` содержит `id` и `join_url`, они сохраняются в сеансе вместе со
статусом `conference_status` (`not_created`, `ready`, `failed`).

Если Телемост недоступен, заявка всё равно создана: сеанс помечается `failed`, а
воркер пробует снова следующим проходом. Настройка `YANDEX_OPTIONAL_SCOPE`
содержит право `telemost-api:conferences.create`; без него Яндекс ответит `403`.

Ссылку организатор получает письмом сразу, гость перед началом.

## Последствия

- **Плюс:** ссылка готова заранее, организатор видит её в панели и в письме.
- **Плюс:** недоступность Телемоста не ломает заявку.
- **Минус:** встреча публична по ссылке; для приватности нужны права и отдельная
  доработка комнаты ожидания.
- **Минус:** удалить встречу через API нельзя, она остаётся в аккаунте Яндекса.
