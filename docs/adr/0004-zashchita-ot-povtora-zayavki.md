# ADR 0004. Один слот это один гость: частичный уникальный индекс

- **Статус:** принято
- **Дата:** 7 октября 2026

## Контекст

Ссылка на страницу записи публичная, и по одному времени могут прийти несколько
запросов одновременно. Нужно не дать двум гостям занять один и тот же слот и не
дать одному гостю отправить форму дважды.

Слоты не хранятся (ADR 0003), поэтому повесить ограничение на `slot_id` нельзя.
Есть `Session`: строка о занятом слоте, которая появляется с первой заявкой.

## Решение

Правило держит частичный уникальный индекс на таблице заявок:

```sql
CREATE UNIQUE INDEX uq_booking_active_session
  ON bookings (session_id)
  WHERE status IN ('pending', 'confirmed');
```

Слот занимает только заявка в статусе `pending` или `confirmed`. Отменённая или
удалённая заявка место не держит, поэтому время снова свободно.

Обработчик заявки проверяет доступность по сетке и возвращает `409`, если время
занято, но настоящая гарантия это индекс: две одновременные заявки не могут
записаться обе.

## Последствия

- **Плюс:** правило держится при одновременных запросах из разных процессов.
- **Плюс:** отмена или удаление заявки освобождает время без отдельного счётчика.
- **Минус:** обработчик один: заявки создаёт ровно один маршрут, иначе гарантия
  ослабнет.
- **Минус:** встреч на много гостей нет; это осознанная граница версии.
